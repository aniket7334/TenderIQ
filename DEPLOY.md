# Deploying TenderIQ for free

| Part | Service | Plan | Address you'll get |
|---|---|---|---|
| Website (React) | **Vercel** | Hobby (free) | `https://<name>.vercel.app` |
| API (Node.js) | **Render** | Free web service | `https://tenderiq-api.onrender.com` |
| Database (MySQL) | **TiDB Cloud** | Starter (free, MySQL-compatible) | a `…tidbcloud.com` host |

XAMPP stays on your PC for local development. The cloud uses its own copy of
the data, which you copy over once in step 2.

> **Free-plan limits to know**
> - **Render Free sleeps after 15 minutes with no visitors.** The first visit after
>   that takes about a minute while it wakes up. While it's asleep, the hourly
>   tender scrape and the 15-minute alert checks don't run — they resume when
>   someone opens the site (or click **Scrape Now / GeM Now** on the dashboard).
> - **Vercel Hobby is for non-commercial use.** If TenderIQ becomes a paid or
>   business product, Vercel requires the Pro plan.
> - **TiDB Starter** has a monthly free usage quota; past it, queries are slowed
>   until next month (or until you set a spending limit).
> - Files uploaded on Render (e.g. note templates) are lost when it restarts.

## 1. Create the database (TiDB Cloud)

1. Sign up at **https://tidbcloud.com** (Google or GitHub sign-in works).
2. **Create cluster → Starter** (free). Pick a region close to India, e.g.
   **AWS Mumbai (ap-south-1)** or **Singapore (ap-southeast-1)**. Name it `tenderiq`.
3. Open the cluster → **SQL Editor** and run:
   ```sql
   CREATE DATABASE tenderiq CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
4. Click **Connect** (top right):
   - Connect with: **General**
   - Click **Generate Password** and copy it somewhere safe (shown only once).
   - Note the **Host**, **Port** (4000) and **User** (looks like `xxxxxxxx.root`).
5. Build your connection string (replace the three parts in CAPITALS):
   ```
   mysql://USER:PASSWORD@HOST:4000/tenderiq?ssl=true
   ```
   If the password contains `@ : / ? #` characters, it still works — TenderIQ
   handles them — but keep the whole string inside quotes in the commands below.

## 2. Copy your data from XAMPP to TiDB (once, on your PC)

Keep XAMPP's MySQL running. In PowerShell, in `D:\tenderiq-main\tenderiq-main\backend-js`:

```powershell
$env:CLOUD_DB = "mysql://USER:PASSWORD@HOST:4000/tenderiq?ssl=true"
```

Create the tables in TiDB:

```powershell
$env:DATABASE_URL = $env:CLOUD_DB; npm run migrate; Remove-Item Env:DATABASE_URL
```

Copy the data (tenders, categories, sources, keywords, documents, your account…):

```powershell
$env:TARGET_DATABASE_URL = $env:CLOUD_DB; npm run copy-data; Remove-Item Env:TARGET_DATABASE_URL
```

Make your own account an admin in the cloud database:

```powershell
$env:DATABASE_URL = $env:CLOUD_DB; npm run make-admin -- aniketbante73@gmail.com; Remove-Item Env:DATABASE_URL
```

Close the PowerShell window afterwards (it clears `CLOUD_DB`, which contains the password).

> The **demo accounts** (`admin@tenderiq.com` / `admin123` etc.) are **not copied** on
> purpose — their passwords are public in the code, so anyone could log in as admin.
> Sign in to the live site with your own account instead.

## 3. Deploy the API (Render)

1. Sign up at **https://render.com** with your GitHub account.
2. **New → Blueprint** → connect GitHub → choose **aniket7334/TenderIQ**.
   Render reads `render.yaml` from the repository and shows a service named
   **tenderiq-api** (Free plan, Singapore).
3. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | your TiDB connection string from step 1 |
   | `CORS_ORIGINS` | `http://localhost:5173` for now (you'll add the Vercel address in step 5) |
   | `APP_URL` | `http://localhost:5173` for now |
   | `OPENAI_API_KEY` | optional — only for AI tender notes; leave empty otherwise |

   `JWT_SECRET_KEY` is generated by Render automatically (a long random secret).
4. Click **Apply**. The first build takes a few minutes.
5. When it shows **Live**, open `https://tenderiq-api.onrender.com/health` — you
   should see `"status":"healthy"` and `"database":"connected"`.
   (If Render gave the service a different address, use that one everywhere below.)

## 4. Deploy the website (Vercel)

1. Sign up at **https://vercel.com** with your GitHub account.
2. **Add New → Project** → import **aniket7334/TenderIQ**.
3. Settings:
   - **Root Directory:** `tenderiq-main/frontend-react` (click *Edit*)
   - **Framework Preset:** Vite (detected automatically)
   - **Environment Variables:**
     `VITE_API_URL` = `https://tenderiq-api.onrender.com/api/v1`
4. Click **Deploy**. You'll get an address like `https://tender-iq.vercel.app`.

## 5. Connect the two

1. Render → **tenderiq-api → Environment**:
   - `CORS_ORIGINS` = your Vercel address, e.g. `https://tender-iq.vercel.app`
     (add more separated by commas, e.g. a custom domain)
   - `APP_URL` = the same Vercel address
2. **Save changes** (Render redeploys automatically).
3. Open your Vercel address, sign in with your own account. 🎉

## Updating the live site later

Push to the `main` branch on GitHub — Vercel and Render both redeploy automatically.
If an update adds database changes, run the migration against TiDB again:

```powershell
$env:DATABASE_URL = "mysql://USER:PASSWORD@HOST:4000/tenderiq?ssl=true"; npm run migrate; Remove-Item Env:DATABASE_URL
```

## Optional: keep the API awake

To keep scrapes and alerts running around the clock on the free plan, a free
uptime service (e.g. cron-job.org or UptimeRobot) can open
`https://tenderiq-api.onrender.com/health` every 10 minutes. One always-awake
service uses about 744 of Render's 750 free hours per month, so this only works
for a single free service. The paid **Starter** plan (~$7/month) stays awake on
its own.

## Troubleshooting

| Problem | Fix |
|---|---|
| Site loads but sign-in fails with a network/CORS error | `CORS_ORIGINS` on Render must exactly match the Vercel address (`https://…`, no trailing path). |
| First request takes ~1 minute | Normal on Render Free — the API was asleep. |
| `/health` shows `database: disconnected` | Check `DATABASE_URL` (user, password, host, port 4000, `/tenderiq`, `?ssl=true`). |
| Pages other than the home page show 404 on Vercel | Make sure the Root Directory is `tenderiq-main/frontend-react` so `vercel.json` is used. |
| Sign-in works but no Admin section | Run `make-admin` (step 2) against the cloud database, then sign out and in again. |
